# 차량 HMI 시스템

STM32 제어부와 Qt HMI를 UART로 연결한 차량 제어·모니터링 시스템.
운전자 얼굴 인증으로 차량을 활성화하고, 주행·환경 정보를 표시하며 이력을 DB에 기록한다.

---

## 개요

운전자가 차량 버튼을 누르면 얼굴 인증이 시작되고, 등록된 운전자로 확인되어야
계기판과 주행 조작이 활성화된다. STM32가 수집한 센서·주행 데이터는 실시간으로
표시되며 SQLite에 저장된다.

```
[운전자 카메라] [후방 카메라]          [온습도 · 초음파 · LED · 버튼]
        │                                        │
   ┌────▼─────────────────┐  UART 115200  ┌──────▼──┐
   │   Qt HMI (Windows)   │◄─────────────►│  STM32  │
   │  UI · 얼굴인증 · DB   │               └─────────┘
   └──────────┬───────────┘
              ▼
        [SQLite DB]
```

## 주요 기능

| 기능 | 내용 |
|---|---|
| 운전자 얼굴 인증 | 얼굴 검출·인식으로 신원 확인, 인증 전 모든 조작 차단 |
| 실시간 모니터링 | 온습도, 주행 상태, 후방 초음파 거리 표시 |
| 영상 표시 | 운전자 카메라(인증 시), 후방 카메라 |
| 차량 제어 | 비상등 토글, 좌·우회전 명령 전송 |
| 이력 관리 | 시스템·주행·환경·인증 로그 저장 및 기간별 조회 |
| 통신 안정성 | 200ms 하트비트로 통신 두절 시 STM32 안전 정지 |

## 화면 구성

좌측 메뉴로 전환하는 6개 화면으로 구성된다.

| 화면 | 내용 |
|---|---|
| 계기판 | 차실 온습도, 주행 속도, 후방 초음파 거리 |
| 후방 카메라 | USB 카메라 영상, 후방 거리 표시 |
| 운전자 인식 | 내장 카메라 영상, 얼굴 등록·인증, 운전자 조회 |
| 주행 조작 | 방향 버튼, 비상등, 모드 전환 |
| 환경 설정 | 선풍기 상태, 임계 온도 |
| DB 조회 | 기간·종류별 로그 조회 |

## 동작 시나리오

```
프로그램 실행     운전자 인식 화면만 활성, 카메라 정지 상태
      │
      ▼
STM32 버튼 ($B)   탑승 신호 → 인식·등록 버튼 잠금 해제
      │
      ▼
[인식 시작]       카메라 기동 → 얼굴 검출·인식
      │
      ▼
인증 확정         5회 연속 동일 인물 → 환영 메시지
      │
      ▼
계기판 화면       전체 화면 잠금 해제, 주행 조작 가능
```

인증 전에는 운전자 인식 탭 외의 모든 화면이 잠기며, 상단에
`모드: 시동 꺼짐 (미인증)` 이 표시된다. 인증이 완료되면 반대로
운전자 인식 탭이 잠긴다.

## 통신 프로토콜

UART 115200-8-N-1, `$<타입>,<인자>...\n` 형식의 줄 단위 메시지.

**STM32 → Qt**

| 메시지 | 내용 | 주기 |
|---|---|---|
| `$D,<온도>,<습도>,<거리>,<속도>` | 센서 데이터 | 500ms |
| `$V,<F\|B\|L\|R\|S>` | 주행 상태 변경 | 이벤트 |
| `$C,<mode>,<on>` | 공조 상태 변경 | 이벤트 |
| `$B` | 차량 버튼(탑승) | 이벤트 |

**Qt → STM32**

| 메시지 | 내용 |
|---|---|
| `$E,<0\|1>` | 비상등 ON/OFF |
| `$M,<L\|R>` | 좌·우회전 명령 |
| `$H` | 하트비트 (200ms 주기) |

## 소프트웨어 구조

```
MainWindow ─ UI 배선 · 인증 상태 관리 · DB 저장
   │
   ├─ SerialLink ─────── STM32 프로토콜 파싱 · 송신 · 하트비트
   │
   ├─ DatabaseManager ── SQLite 연결 · 스키마 · 저장 · 조회
   │
   ├─ CaptureThread(사용자캠) ─┬─ DisplayThread ─────→ 영상 표시
   │                           └─ RecognitionThread ─→ 검출 · 인식 루프
   │
   ├─ CaptureThread(후방캠) ──── DisplayThread ─────→ 영상 표시
   │
   └─ FaceEngine ─────── Haar 검출 + LBPH 인식 연산
```

### 설계 원칙

**카메라 1대당 `CaptureThread` 는 하나만 만든다.**
여러 화면에 같은 영상을 쓰려면 소비자를 여러 개 붙인다.
DirectShow 는 같은 장치를 두 번 열면 실패한다.

**DB 접근은 UI 스레드에서만 한다.**
`QSqlDatabase` 커넥션은 생성한 스레드에서만 사용할 수 있으므로,
워커 스레드는 시그널로 데이터를 넘기고 저장은 `MainWindow` 가 수행한다.

**스레드 종료는 소비자 → 생산자 순서로 한다.**
반대로 하면 소비자가 해제된 객체를 참조할 수 있다.

## 향후 과제

- 가변 PWM 기반 모터 속도 제어
- 전·후·좌·우 초음파 센서 확장 (자동 주행 모드)
- 얼굴 벡터(임베딩) 기반 인증으로 전환 — 원본 이미지 미보관
- 로그아웃 기능 및 재인증 흐름 정리
- 미연결 UI 요소 처리 — 공조 제어 명령(`$F`), 전진·후진·정지 버튼
